# 原题纯净版 vs 增强版：卡面脚手架值多少分

> **增强版** `tasks/T*.md`：赛题原文 + 输入 / 判据定义 / 输出要求 / 答案字段名 / 约束
> **纯净版** `tasks/raw/T*.md`：只有赛题原文 + 一条运行时信息（`rawcards.py` 生成）
> 同批题、同模型、同预算（100 轮 / 420 s）。三列判据：
> **增强·严格** = bench 实际用的按键取值；**增强·宽松** / **纯净·宽松** = 期望值出现在答案任意位置即可。
> 加「增强·宽松」这一列，是为了把「卡面影响」与「判据宽严影响」分开。

## 结论

1. **脚手架对总分没有影响**：9/22 vs 9/22（三列全一样）。原先我猜「10/24 是靠字段名撑起来的」——**被这次对照否掉了**。
2. 逐题有个别互换，都是行为差异、不是系统优势：
   - **纯净版赢**：T07（+2）、T02（+1）。T07 增强版 39 轮判「证据不足」，纯净版 36/39 轮直接给出 18.75 与 3.539；差别在于增强版要求按键填 `cube_volume_after_m3`，它把力气花在凑字段上。
   - **增强版赢**：T04（+2）、T09（+1）。T04 纯净版其实**算对了**（给出占地矩形 x∈[5.07,5.53]、y∈[-0.63,-0.13]，中心就是 5.3/−0.38），但它没显式写"中心"这个量——按「交付是否完整」判失败，按「算得对不对」算通过。T09 纯净版一次只点到 15/16 个实体。
3. **纯净版更省**：卡只有 200~500 字符（增强版 2~4k），T01_1 从 40/42 轮 595k 降到 26/33 轮 436k。
4. **真正的瓶颈没变**：T03（宽深搞反）、T05、T06、T08、T10 两版都失败，而且失败方式一样——重复取数、撞 100 轮、答「无法确定」。**换卡面救不了这些。**

## 顺带修掉一个真 bug

纯净版第一次跑的时候，T06 4~8 轮就判「模型文件无法读入」放弃：卡里写的是 `$MODEL` 占位符，运行时没人替换，模型自己猜路径，把 `AI-Geometry-Models` 猜成 `AI_Geometry-Models`（连字符 → 下划线），连错 7 次。

现在 `run_agent.py` 在读卡后把 `$MODEL` 换成 `--model` 的真实值。修完 T06 从「8 轮放弃」变成「99/100 轮耗尽」——**与增强版完全一样**，说明它的病是收不了口，不是读不进模型。
