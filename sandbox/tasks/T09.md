# 任务卡 · T-09

> 本卡是智能体在本次运行中收到的**全部**任务信息。卡内不含识别结果、不含对象编号、
> 不含解题步骤。运行开始时对卡做 SHA-256，写入账本首条记录。

## 题目原文（赛题 Task 09）

根据几何形状识别房间中的物体。

1. 从所选格式中提取房间内实体的几何形状和位置。识别过程只能读取这些几何信息，
   不得使用名称、类别、材质、父子关系或自定义属性。需要编号时，自行使用不含类别含义的编号，
   不沿用文件中的类别标记。
2. 识别地板、墙、门及其附件、窗及其组件、画框和椅子。一个物体由多个部件组成时，
   需在结果中标出这些部件；同一几何对象包含多件物体时，标出对应区域。
3. 区分窗户和画框，结合墙体是否有贯通开口等几何证据解释判断。
4. 给出门、窗分别属于哪面墙，画框贴在哪面墙上，以及椅子位于哪个房间。
   仅凭几何不能确定的结果标为「未知」，说明缺少什么信息；不得改变形状或位置。

## 输入

- 模型文件：`$MODEL`
- 格式未知、单位未知、朝向未知。**文件里的名称、类别、材质、父子关系、自定义属性一律不可用**，
  读取时须显式关闭元数据。
- 文件里同时装着多组互不相连的模型，本题只用房间那一组（实体数最多的那组）。

## 判据定义（逐条固定，按此计算）

- **编号**：自行编号，编号本身不得含类别含义（不能叫「door_1」「window_2」这类）。
  本文用加载顺序编号，编号只表示「它是第几个被读到的实体」。
- **地板**：水平薄板，平面尺寸最大、厚度远小于另两维。
- **墙**：竖向薄板，厚度约为层高的十分之一量级、高度显著大于厚度与另一水平尺寸。
- **墙体贯通开口**：墙体实体的体积小于其包围盒体积（填充率 < 1），且缺口体积等于
  某个穿墙盒状体在墙厚方向上的截面体积 —— 两者一致才叫「贯通」，只小一点可能是倒角。
- **门及其附件**：与门洞相伴的部件组。附件指贴近门扇的独立小构件（把手）。
- **窗及其组件**：与窗洞相伴的部件组，含框与透光件（薄片）。
- **画框**：贴在**没有贯通开口**的墙面上的框状件，及其内侧的薄板。
- **归属**：部件与某面墙的贴合面积最大者，判为属于该墙。贴合面积为 0 时用最小包围盒间隙定位，
  但结论要注明依据是「相邻」而不是「贴合」。
- **房间**：一块地板及其围合的墙体构成一个房间。

## 输出要求

1. 每个实体一行：编号、几何尺寸、位置（包围盒中心）、判定的角色、判定所依据的几何量。
2. 多部件物体：列出部件编号，并说明它们靠什么几何关系被判为同一件物体
   （贴合面积、包含关系、相对位置）。
3. 窗与画框的区分：给出**两面墙的填充率对比**与缺口体积，说明为什么一个是洞、一个是整墙。
4. 归属结论：门属于哪面墙、窗属于哪面墙、画框贴在哪面墙、椅子在哪个房间。
5. 「未知」项：逐条列出，并说明缺什么信息才能判定。没有未知项时明确写「无」。
6. 不得出现任何来自文件的名称、类别、材质、属性；判定依据只能是尺寸、位置、贴合与包含关系。

## 约束

- 只能通过沙盒注册的工具接触几何；不得直接读文件内容做判定。
- 读取时须关闭元数据（`keep_metadata=false`），否则名称会污染识别。
- 本题只识别，不改变任何形状或位置。
- 结论中的每个数字都必须能追溯到某一次工具调用的返回值。
